🎯 INTERVIEW QUESTIONS & ANSWERS
🔹 Q1: What was the biggest challenge in your DevOps project?

Answer:
The biggest challenge was Jenkins build scheduling delays due to executor starvation and node going offline caused by low disk and temp space. I analyzed system metrics using df -h and free -h and resolved it by cleaning disk and restarting services.

🔹 Q2: Why was Jenkins build stuck at "Waiting for next available executor"?

Answer:
Because the built-in node was either offline or all executors were occupied. Jenkins requires a free executor to schedule builds.

🔹 Q3: Why did Jenkins go into paused/shutdown mode?

Answer:
Jenkins detected disk space below its configured threshold (1GB), so it paused builds to protect system integrity.

🔹 Q4: How do you troubleshoot a slow Jenkins build?

Answer:

Check executor availability

Check node status

Verify disk space (df -h)

Check memory usage (free -h)

Check temp directory usage

Restart Jenkins if required

🔹 Q5: What is an executor in Jenkins?

Answer:
An executor is a worker thread on a Jenkins node that runs builds. Each executor can run one job at a time.

🔹 Q6: Why is /tmp important in Jenkins?

Answer:
Jenkins uses /tmp for temporary workspace and build files. If temp space is below threshold, builds pause.

🔹 Q7: Difference between agent any and specific agent?

Answer:

agent any → runs on any available node


agent { label 'linux' } → runs on a specific labeled node

3️⃣ What is an executor in Jenkins?

Answer:

An executor is a worker thread on a Jenkins node that runs builds.

1 executor = 1 build at a time

If no executor is free → Build waits

In my project, builds were stuck at:

“Waiting for next available executor”

Because executors were busy or node was offline.

Node status

Disk space (df -h)

Memory (free -h)

8️⃣ What is Declarative Pipeline?

Answer:

Declarative Pipeline is a structured Jenkins pipeline syntax that uses:

pipeline

agent

stages

steps

Example from my project:

pipeline {
  agent any
  stages {
    stage('Build') {
      steps {
        sh './legacy_app.sh'
      }
    }
  }
}


It improves readability and maintainability.

9️⃣ What is the difference between CI and CD?

Answer:

CI (Continuous Integration) → Automatically build & test code on commit

CD (Continuous Delivery/Deployment) → Automatically deploy to environments

My project focused on CI pipeline implementation.
